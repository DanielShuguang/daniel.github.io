Rust 不安全编程 ​

为什么 Rust 要有 unsafe ​

Rust 语言的特点就是在不进行手动内存管理的基础上，提供了一些高级的抽象和强大的性能。但是作为一门系统级语言，若是想要有较好的开发体验和执行效率，实际开发中没有办法完全不操作原始指针，有些场景直接操作原始指针也会使代码可读性和性能更好，比如 Rust 提供的一些常用数据结构的实现就是基于 unsafe。因此 Rust 提供了 unsafe 关键字，允许开发者在 Rust 中进行一些不安全的操作。

如何使用 unsafe ​

在 Rust 中，unsafe 关键字只能用于两种情况：

  1. 块中，表示该块可能会发生不安全的操作。
  2. 函数声明中，表示该函数可能会发生不安全的操作。

块中 ​

在块中，unsafe 关键字表示该代码块可能会发生不安全的操作。例如，下面的代码块中通过原始指针修改了数组元素，因此使用了 unsafe 关键字。

rust
fn main() {
    let mut arr = [1, 2, 3];
    unsafe {
        let p = arr.as_mut_ptr();
        *p.offset(0) = 4;
    }
    println!("{:?}", arr); // [4, 2, 3]
}

函数声明中 ​

在函数声明中，unsafe 关键字表示该函数可能会发生不安全的操作。例如，下面的函数声明表示该函数可能会修改全局变量：

rust
static mut GLOBAL_VARIABLE: i32 = 0;

unsafe fn modify_global_variable() {
    println!("Global variable: {}", GLOBAL_VARIABLE); // Global variable: 0

    GLOBAL_VARIABLE = 1;

    println!("Global variable: {}", GLOBAL_VARIABLE); // Global variable: 1
}

在调用该不安全函数时，也要使用 unsafe 块包裹执行。

rust
fn main() {
    unsafe {
        modify_global_variable();
    }
}

unsafe 不等于完全不检测 ​

Rust 的借用规则时所有权系统的一个重要部分，即便是在 unsafe 函数中，Rust 的编译器仍然会检查借用规则。所以我们仍无法同时存在可变借用和不可变借用，即使它们都是通过 unsafe 函数创建的。

rust
unsafe fn borrow_with_unsafe() {
    let mut x = 5;
    let y = &mut x;
    let z = &x;
    *y += 1;
    println!("x = {}", x);
}

执行代码后会报错：

cannot borrow `x` as immutable because it is also borrowed as mutable

例子 - 链表实现 ​

链表实现是一个常见的数据结构，它通常用于存储有序的数据。以下是一个基于 unsafe rust 的简单的链表实现：

rust
use std::ptr;

// 定义链表节点
struct Node<T> {
    value: T,
    next: *mut Node<T>, // 使用裸指针指向下一个节点
}

// 定义链表
pub struct LinkedList<T> {
    head: *mut Node<T>, // 指向链表头节点
}

impl<T> LinkedList<T> {
    // 创建一个新的空链表
    pub fn new() -> Self {
        LinkedList {
            head: ptr::null_mut(),
        }
    }

    // 在链表头部插入一个新节点
    pub fn push_front(&mut self, value: T) {
        let new_node = Box::into_raw(Box::new(Node {
            value,
            next: self.head, // 新节点的 next 指向当前头节点
        }));
        self.head = new_node; // 更新头节点为新节点
    }

    // 从链表头部移除一个节点并返回其值
    pub fn pop_front(&mut self) -> Option<T> {
        unsafe {
            if self.head.is_null() {
                return None; // 链表为空
            }
            let old_head = Box::from_raw(self.head); // 获取头节点的所有权
            self.head = old_head.next; // 更新头节点为下一个节点
            Some(old_head.value) // 返回旧头节点的值
        }
    }

    // 遍历链表并打印所有节点的值
    pub fn print_list(&self)
    where
        T: std::fmt::Debug,
    {
        let mut current = self.head;
        while !current.is_null() {
            unsafe {
                println!("{:?}", (*current).value);
                current = (*current).next;
            }
        }
    }
}

// 手动实现 Drop trait，确保释放所有节点的内存
impl<T> Drop for LinkedList<T> {
    fn drop(&mut self) {
        let mut current = self.head;
        while !current.is_null() {
            unsafe {
                let node = Box::from_raw(current); // 获取节点所有权
                current = node.next; // 移动到下一个节点
            }
        }
    }
}

安全 Rust 使用 Option 来避免空指针错误，如果熟悉 C# 或者 Typescript 的话，应该会熟悉这种可空类型的设计。但是在 unsafe rust 中，就不可避免地接触到其他语言中必须要小心的 null 指针问题，安全起见，每次访问原始指针时，都需要进行非空判断。
